# SILENT DEPTH V2.3 — Local GLB & Cinematic Naval Upgrade

**Status:** Implemented with evidence-bound acceptance
**Scope:** Rendering, local assets, UI presentation, and capture only
**Non-goals honoured:** No modification to Simulation Engine, AI, sonar mechanics, physics, difficulty, mission content, map, progression, controls, save data, combat resolution, or test fixtures.

## Executive summary

V2.3 establishes the first project-owned, offline-capable GLB asset path for **SILENT DEPTH**. The renderer can now resolve approved local GLB assets from a versioned registry, cache source scenes, clone visual instances, and fall back to established procedural families if any model is unavailable or invalid. The player submarine has a four-level GLB family; the priority Destroyer and Tanker classes each have a three-level GLB family. Every exported model is generated from repository-owned Blender scripts, is recorded as CC0 project-owned content, has a SHA-256 value in the registry, and has an explicit procedural fallback.

The visual layer also adds a direction- and speed-driven player wake, a storm-volume sky pass, a cold water-column read for depth charges, a low-threat world-first HUD state, and a short F12 cinematic capture window. These features consume only pre-existing `RenderState` / `GameSnapshot` facts and do not emit commands or mutate authoritative world state. The latest automated regression run passed **32 test files / 506 tests**, strict TypeScript checking, and production compilation.

> **Evidence-bound result:** V2.3 is a functional production asset pathway, not yet a substantiated claim of a `>=7/10` storefront visual score. Direct Chromium observation confirms normal M05 initialization with the GLB-capable build and the world-first HUD. The automation session did not yield a readable GLB ship close shot, a combat impact frame, or direct synthetic-F12 verification after injected key presses transitioned the test viewport to `about:blank`. These remain explicit target-hardware capture gates rather than inferred successes.

## 1. Delivered rendering and asset work

| Area | Delivered V2.3 work | Behavioural boundary |
|---|---|---|
| Asset system | `AssetManager` loads only approved local GLB entries, caches source scenes, clones per visual entity, releases shared resources, and returns fallback semantics on any failure. | No runtime network fetch; no simulation access. |
| Asset governance | Versioned V3 registry includes origin, license URL, author, commercial/modification permissions, hash, triangle count, material intent, LOD, status and fallback mapping. | External assets remain blocked until their local files and licenses are registered. |
| Player submarine | Project-owned LOD0–3 GLB family with wet hull, anti-slip deck, metal mast, bridge-glass and wear material groups; existing procedural model remains an unconditional failure fallback. | Position, heading, propeller/rudder response still come only from existing `RenderPlayer`. |
| Priority enemy ships | Project-owned Destroyer and Tanker LOD1–3 GLB families. Other ship classes remain on the existing procedural route. | `visible` still gates every entity before renderer instantiation. |
| Ocean | Existing multi-scale water is augmented by local, speed/heading-driven stern foam. | Wake is a shader uniform; it does not modify drag, buoyancy, speed, or detection. |
| Storms | Existing GPU rain and deterministic flash are retained; sky gets a broad low-cloud storm mass and restrained cold rim. | Weather kind and values remain adapter-owned read-only data. |
| Combat FX | Existing torpedo impact retains warm flash/debris profile; depth charge gains a cold expanding water column in addition to its shockwave. | Effects are spawned only from existing adapter-provided events. |
| HUD | Existing low-visibility UI transitions into `hud--quiet` only when `MISSION_RUNNING`, no contacts/lock, and detection is under 20; it automatically restores on the next update when conditions change. | Cards and input remain available; no command or selection change. |
| Capture | F12 adds a 1.6-second `cinematic-capture` DOM state, hides UI overlays, exports the already rendered WebGL canvas, and restores UI automatically. | No pause, input pulse, camera mode, save, or simulation state is changed. |

The authoring scripts are retained in `tools/assets/`. Their outputs are intentionally small enough to keep the project offline-first and enable quick fallback. They establish a real GLB lifecycle and material/LOD contract, rather than claiming that small procedural-origin meshes are equivalent to commissioned art.

## 4. Commits and workspace hygiene

This implementation follows the existing repository history without deliberately staging unrelated pre-existing changes. Earlier V2.2 work remains isolated in its own commits. V2.3 asset-pipeline work was committed separately before this visual pass. The final V2.3 commit should contain only the explicitly listed GLB files, project-owned Blender generators, asset registry / manager work, renderer integration, visual-only environment/UI/FX changes, V2.3 tests, QA evidence and documentation.
