# SILENT DEPTH：产品定位与首发范围

版本：0.2；日期：2026-09-14；性质：详细设计提案，不是功能验收或最终商业承诺。
用户已确认 UE4 唯一主线与 Steam 发售目标；其余建议见 [决策记录](11_DECISIONS.md)。

## 1. 产品定义

SILENT DEPTH 是一款现代潜艇题材的独立战术游戏。玩家作为艇长，在有限情报下选择
航路、监听方式、攻击窗口与撤离时机，通过任务积累研究点，解锁潜艇与合法装备。

产品承诺的核心不是“拥有所有型号”，而是“每次出航都要判断何时听、何时打、何时走”。
海洋和潜艇模型提供沉浸感；信息博弈、可解释的敌方反应与成长选择提供重复游玩的理由。

## 2. 已确认的边界

- 唯一引擎：Unreal Engine 4.27；不转向 UE5，也不建立浏览器版本。
- 发行目标：Steam 上架的独立游戏；尚未确定售价、日期、发行主体或商店功能。
- 现有 UE4 代码和资产是起点；不因重新设计而默认清空或全面重写。
- 不维护 Web，不做双端同步，不沿用其数值或任务作为新产品的强制验收基线。
- 本轮交付文档，不修改玩法、资产、存档或经济配置，不执行平台上传。

## 3. 建议的市场与体验定位

| 维度 | 建议方向 | 设计后果 |
|---|---|---|
| 玩家 | 喜欢海战、潜行和舰艇成长，但不愿先学习大量专业仪表的玩家 | 先教战术判断，系统辅助解算 |
| 操作身份 | 艇长，而非每个岗位的操作员 | 主要控制航行、传感器、武器与反制 |
| 真实性 | 可信的战术关系，不模拟所有工程细节 | 型号资料与游戏数值分开标识 |
| 游玩方式 | 本地离线单人任务制 | 不需要匹配、账号服务器或常驻联网 |
| 商业模式 | 买断制建议 | 不设计体力、每日任务、付费货币和强制重复劳动 |
| 首发平台 | Windows x64 建议，优先验证 DX11 | 不同时承诺 macOS、Linux、主机或 Steam Deck |
| 语言 | 简体中文优先，英文作为首发候选 | 从第一天使用本地化文本键，不提前宣称翻译完成 |

## 4. 三个设计支柱

1. **先获得优势，再发射武器。** 监听、阵位和攻击时机是主动决策，不是等待冷却。
2. **敌人会反应，但不能全知。** 搜索依据是它实际获得的接触和最后已知信息。
3. **成长改变选择，不替代技巧。** 升级可改善能力，但不能把隐蔽与机动的取舍消除。

失败需要能通过事件和玩家行为解释。未知信息可以制造紧张，错误反馈不能制造混乱。
首次升级应让玩家看出下一次出航的差异，而不是要求先刷许多次同一任务。

## 5. 首发范围建议

以下是用于评估制作量的候选目标，不是已经批准的开发配额或商店承诺。

| 项目 | 首个完整切片 | 首发候选目标 |
|---|---|---|
| 玩家艇 | 1 艘，优先评估现有 Akula 接线 | 6 艘攻击核潜艇，形成至少两种战术侧重 |
| 任务 | 1 次护航运输线截击，含返港与研究 | 3 个教学环节、12 个正式任务、固定种子的复玩变体 |
| 海域 | 1 个有明确接敌与撤离空间的海域 | 3 类海域：近岸、海峡、开阔海域 |
| 敌方 | 运输船、护航水面舰 | 上述两类加敌方潜艇；各有可读且公平的搜索行为 |
| 武器 | 1 类可用鱼雷、有限诱饵 | 少量有实际差异的鱼雷与反制，不按资产数量等比例扩张 |
| 成长 | 1 次研究、1 次合法换装 | 可完成且无需强制重复刷分的舰艇与装备路线 |
| 功能 | 港口、简报、战斗、战报、保存 | 完整设置、输入配置、本地化、战斗中断续玩和发布包 |

艇号、路线和任务配额的具体提案见 [内容目录](15_CONTENT_CATALOGUE.md)，
首轮参数见 [调参基线](13_TUNING_BASELINE.md)，需经对应决策批准后实施。
现有资产工单的生产优先级不是首发名单。
若敌方潜艇无法通过公平性与试玩门禁，必须明确调整首发范围和商店描述，不能以占位替代。

## 6. 明确排除的首发工作

- 多人对战、合作、匹配服务器和反作弊。
- 无缝开放世界、完整艇内步行、艇员日常管理、反应堆操作模拟。
- 战略核打击、弹道导弹核潜艇常规竞技路线，以及为了消耗资产而添加的武器系统。
- 日历驱动任务、联网经济、内购、强制登录、遥测和远程运行时资产。
- 自动承诺创意工坊、云存档、成就、完整手柄支持、抢先体验或其他平台认证。

排除不等于永久禁止。未来新增须说明玩家收益、制作与维护成本、依赖和验收方式。

## 7. 待试玩验证的体验目标

| 假设 | 初步目标 | 验证方法 |
|---|---|---|
| 新手进入决策足够快 | 教学开场约 2 分钟内出现可操作的有效接触 | 记录首次有效接触时刻和玩家是否理解 |
| 标准任务适合一次坐下游玩 | 约 15–25 分钟 | 记录完成、失败和退出时长分布，不人为强制截断 |
| 失败可解释 | 玩家能说出至少一次影响结果的选择 | 试玩结束后开放提问，不给答案诱导 |
| 科技树提供近期目标 | 教学结束后的首次正式成长选择可负担 | 从零存档测试实际奖励与合法候选 |
| 基础战斗自身有吸引力 | 无额外解锁奖励时仍有人主动选择再玩 | 观察选择和原因，不用下载量替代可玩性 |

这些数字不是配置、性能结果或商店文案。试玩程序见 [测试与发行](10_QA_AND_STEAM_RELEASE.md)。

## 8. 完整游戏的定义

从全新安装开始，玩家能理解入口、完成教学、执行任务、失败重试、结算成长、保存退出、
再次继续，最后完成首发内容。所有承诺的系统和内容通过 UE 编译、自动化、编辑器、
发布包和目标硬件验证，且资产许可与商店描述对应实际交付。

“模型可看”“按钮存在”“自动化通过”“Steam 可售”是不同层面的结果，不互相代替。

## 9. 0.2 版范围裁决

本轮把正常流程、失败路径和高风险组合写成具体方案，不声称穷尽无限场景。
[场景矩阵](12_SCENARIO_MATRIX.md)是场景清单入口；每行都有触发、预期、恢复与实施归属。
没有列入首发的机制不默认存在：不支持战斗时间加速、自由航路编辑、多用户同时运行、
手动切换多份生涯档案、任务中途换艇、装备出售或反向洗点。

拟定首发默认是一个本地生涯档案、一个活动任务、一个自动续玩检查点；
标准键鼠、简体中文完整覆盖。英文、成就、云存档和完整手柄是独立候选包，
未批准时不显示相关入口，不以“占位功能”上线。Steam 销售不要求这些候选包全部纳入。

所有生涯档案操作在本地完成；不要求账户绑定。没有授权的免费/付费下载内容不进入界面。
结束全部行动后保留生涯和复玩，不自动清档、不强制开启新周目。
首发不加入中立交通和友军编队，但声学武器没有魔法敌我识别，误伤自身仍按战斗规则裁决。
首发只做船体损伤及其噪声影响，不制作机动/传感器子系统损坏与修理流程。

Steam 当前提交要求、实际可玩性和性能证据。它们在决策/发行文档中有负责人和阻塞节点。
