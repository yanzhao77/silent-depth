# 成长经济与存档规格

版本：0.2；日期：2026-09-14；性质：成长与持久化详细提案。
当前契约仍见 [科技树决策](../UE4_TECH_TREE_DECISION_RECORD.md)和
[科技树 schema](../UE4_TECH_TREE_SCHEMA.md)。本文件不直接覆盖配置或既有存档语义。

## 1. 当前规则与建议分离

当前 `research_cost.json` 为层阶成本系数 100、首次奖励 50、分数除数 10、
最低奖励分数 400、层阶前置解锁数量 1。账户默认研究点为 0。
这些数值描述当前配置，不是新产品经济已平衡的证据。

新方向建议保留一种研究点资源，取消单独购艇银币、维修费、体力和真实时间研究等待。
节点研究完成后直接授予声明的使用权；需要区分艇、装备、能力节点，不把所有节点都当实体装备。

## 2. 起步与拥有权

- 新档案通过有版本的起始清单一次性授予一艘可用艇及完整合法基础配装。
- 教学可使用独立借用艇，不计永久拥有，不允许借用装备被写入永久档案。
- 跳过教学仍能使用起始清单；首次奖励和初始授予分别记账，重进不重复发放。
- 失败后保留已拥有艇与基础配装，不形成没有资源就无法出航的死锁。
- 回退模型只处理表现加载失败，不能让未拥有或被禁止的平台变成可用艇。

起始艇具体 ID 见内容目录，授予方式与余额见本文件 §10；须经 GAME-013/GAME-022 批准；
不能在 UI 里偷偷把所有节点标为解锁，也不能为了演示在生产账户注入测试点数。

## 3. 玩家看到的科技树

舰艇研发为主入口；装备研发从当前艇进入，按武器、传感器、防御、推进分组。
保留现有五类数据，不为新界面新建第二份解锁状态。

国家和战术角色可作筛选；屏幕上的连线只来自真实前置关系。
现有“类别中最近低层阶已解锁一个”的门槛不是国家分支依赖，不能画成按国家逐艇爬升。
若批准国家路线，必须一起更新源数据、服务规则、候选筛选与存档兼容测试。

每个可研究项需显示用途、能力变化、成本、真实前置、资料性质和资产状态。
研究与装备是两个动作：研究授权不绕过平台兼容、socket 容量、任务限制和装备冲突。

## 4. 配装事务

选择平台 -> 查询已拥有且合法候选 -> 预览能力变化 -> 确认 -> 原子保存 -> 刷新展示。
确认时重新执行校验，防止预览后状态变化造成非法配置。失败保留旧配装并显示具体原因。
同一 socket 超容量、未知 ID、没有合法挂点或未经批准的推测配发都不得强行通过。

只有数据库的能力可以不改变外观，但必须确实有已批准的规则效果；
不能把“没模型”自动当“不能研究”，也不能把“有模型”自动当“可以装备”。
未批准的 `GAMEPLAY` 推测兼容仍受既有 DEC-005/GAME-026 约束。

## 5. 奖励与节奏

建议权重方向是主要目标与撤离优先，隐蔽与武器效率提供额外收益，击沉数量不单独主导。
新提案的失败与中止收益为 0，详见 §10；GAME-022 批准前不改变当前代码规则。

| 待验证目标 | 方法 |
|---|---|
| 第一项有意义的升级可负担 | 从零档案执行教学和初次任务，核对真实候选与余额 |
| 主路线不需要强制重刷同一关 | 将首发必经任务保守收益与必要路线总成本一起模拟 |
| 新艇保留战术差异 | 比较任务完成方式，不只比较面板总分 |
| 低难度反复刷分不是唯一最优解 | 对比每局时间、风险和收益，而非添加真实时间限额 |

首轮成本与收益在 §10 与内容目录给出；它们可用于预算验证，但尚未通过试玩平衡。

## 6. 同一场结算只能生效一次

现有按任务 ID 防重复首通奖励不足以识别同一场结果的重复提交；
正常重玩同一任务仍应按规则获得收益，不能简单把任务 ID 永久锁死。

新契约建议采用持久化的本地任务序号产生唯一任务实例 ID，与任务类型 ID 分离：

1. 出航事务持久化保留下一个序号和本场身份；失败不启动仿真。
2. 仿真产生唯一终态，冻结包含实例 ID 的结果。
3. 会话层验证结果属于当前活动任务，计算研究、统计、首通和解锁的候选档案。
4. 在同一候选档案里记入已结算实例标记，并清除活动任务，再通过存档层提交。
5. 保存失败保留待结算状态，允许重试；不显示已到账，不先修改长期账户。
6. 重复提交、重复打开战报或恢复旧活动任务不再次发奖。

采用严格单活动任务序号和结算高水位限制账本增长；具体恢复与旧档迁移见
[存档协议](14_SAVE_RECOVERY_PROTOCOL.md)，必须在 schema 任务中证明后落地。
不能仅依赖内存布尔值、墙钟或 UI 按钮禁用防重。

## 7. 两类保存内容

| 内容 | 保存范围 | 兼容要求 |
|---|---|---|
| 长期档案 | 拥有、研究、配装、任务进度、统计、结算标记、设置 | schema 版本、有效 ID、交易一致性、旧版本迁移 |
| 活动任务 | 任务与规则版本、配置指纹、固定 tick、全部必要权威状态、RNG 状态、输入队列边界 | 恢复后与不中断运行相同；不能只存 seed 或表现快照 |

港口状态与战斗恢复分别校验；无法恢复旧战斗时保留长期档案并解释原因，不默默重开领收益。
暂定首发支持一个活动任务的暂停保存与继续，不先做任意时刻多槽快速回档系统。
仅同一受支持版本和配置下承诺回放/恢复一致，不承诺跨版本轨迹逐位相同。

## 8. 可靠性与平台边界

存档保留临时写入、读回校验和恢复策略，但必须用故障注入检验每个写入阶段。
损坏文件不得静默清空；允许保留故障副本、恢复已验证备份或由用户明确选择新档。
云存档是否启用另行决定；联网冲突不能按研究点最大值合并，也不能把 SDK 回调写入仿真。
退出时有未提交结果需明确处理，不因切换关卡丢失待保存状态。

## 9. 验收用例

- ECO-001：全新档案、跳过教学、重进教学均可出航且授予不重复。
- ECO-002：不足余额、非法前置、超容量装位失败后余额和配装不变。
- ECO-003：同实例结算两次只到账一次；同任务新实例可合法再次结算。
- SAV-001：每个持久化阶段模拟写失败、关闭和重启，既不重复奖励也不破坏旧档。
- SAV-002：不中断与保存恢复的战斗在相同输入下得到相同结果。
- SAV-003：未知版本、无效 ID、缺配置和损坏数据产生可解释错误，不自动解锁内容。

## 10. 首轮经济参数与评价公式

新档案一次授予 LosAngeles、完整合法基础配装和 100 研究点；不要求先通过教学。
教学只记录完成，不给额外货币，避免跳过或重进产生起步差异。首次 100 点可研究降噪推进配置。
出航不扣研究点，弹药/诱饵按已冻结配装每场补足；失败不扣拥有权，无维修、售艇、洗点机制。

正式任务胜利评价：主要目标 500 + 撤离 200 + 次要目标 100 + 全程未主动发射声呐 100 +
武器效率 50 + 船体保全 50，取整数，总分 700–1000。
武器效率为重型鱼雷消耗不超过任务阈值，任务未指定时阈值 4；船体保全为返航船体至少 70。
侦察/突破零发射可得效率分，但不会改变该任务主要目标；多目标只在主要目标全部满足才给基础分。
失败和中止评价为 0，但战报仍显示真实完成项与感知事件，不抹去玩家行为。

胜利研究点 `200 + floor((score-700)/3) + firstClearBonus`；首次奖励为 100，之后为 0。
首通按任务类型记录，标准与变体共享首次奖励；只有标准首次胜利推进下一关开放。
失败、中止、教学均为 0；同实例不重复发奖。评价分与奖励不使用墙钟或联网状态。

预算：12 关最低首次胜利共 3600，加起始 100 为 3700；全部艇与四项改进合计 4000。
因此首发主路线可不刷关，收藏全部内容可能需要重玩或更高评价；入门艇能完成全部任务，
不出现必须解锁某高级艇才能赚到解锁它的钱。此预算是算术，不是可玩性或实际通关证明。
旧账户规则与本提案不同，实施需更新独立经济版本并说明已投入资源的迁移政策。

## 11. 研究与配装交互边界

同一事务运行时其他研究/换艇/出航动作禁用；重复确认返回同一个请求结果，服务仍需防重。
点击预览不花费，取消预览不影响档案；确认前数据版本或余额变化则重新计算并要求再次确认。
已研究节点再次确认只返回已拥有，不退款也不重复扣款。无合法装备映射不能通过研究直接变可装备。
选艇立即成为港口预览选择，只有保存成功才成为下次出航的档案选择；取消回到原已保存艇。
配装页面有修改时返回弹出“保存 / 放弃修改 / 继续编辑”；放弃只丢草稿，不移除已拥有装备。
更新移除某装备时必须走迁移，不把配置自动替换为更强装备；没有合法恢复方案则显示不可出航。

## 12. 生涯维护

首发一个本地档案；重置生涯须二次确认并键入明确确认词，先导出只读备份再创建新档案身份。
重置后旧任务结果和检查点不可提交给新档案；不会把旧首通标记、余额与新拥有列表混合。
不提供分拆导入余额或装备的接口；恢复只能选择完整已验证档案，失败不修改当前记录。
全部行动完成后保持所有权和当前选择，显示继续复玩入口；已经全研究时不再显示虚假下一节点。
