# 完整游戏设计

版本：0.2；日期：2026-09-14；性质：详细设计提案，不是实现声明。
范围依据：[产品定位](00_PRODUCT_SCOPE.md)；系统细节不在本文件重复定义。

## 1. 玩家幻想与核心问题

玩家指挥一艘现代潜艇完成局部海域行动。主要挑战不是看到敌人后更快按发射键，
而是在不知道全部事实时，决定继续获取情报、抢占位置、出手或撤退。

每项玩法至少服务一个问题：

- 我目前知道什么，哪些只是估计？
- 我采取这个行动会获得什么，也会暴露什么？
- 主要目标是否值得继续冒险，何时应当保存自己？

港口让玩家理解“我将带什么能力出航”；任务让这些能力产生差别；研究让下一次出航有目标。

## 2. 三层循环

| 时间尺度 | 循环 | 玩家收获 |
|---|---|---|
| 数十秒 | 监听、判读、调整航速或深度、重新评估 | 信息质量或战术位置发生可理解变化 |
| 一局 | 简报、接敌、攻击或侦察、应对反扑、撤离、战报 | 完成目标、理解错误、获得研究收益 |
| 多局 | 选任务、研究、配装、换艇、挑战新情境 | 新战术选择与完成首发行动的长期目标 |

不得只靠奖励推动重复游玩。即使暂不发研究点，单局也应保留明确选择和可归因结果。

## 3. 首次启动

1. 检查本地配置和存档版本；失败显示可恢复的错误，不悄悄覆盖旧档。
2. 提供语言、显示、音量和必要无障碍设置；无账户登录或必需联网步骤。
3. “开始训练”为推荐入口，已有存档则优先显示“继续”。教学可跳过和重进。
4. 使用预配置的训练借用艇；不先要求选国家、阅读全部研发节点或购买装备。
5. 教学完成后返回港口，展示初始拥有艇和第一项可负担的研究选择。

初始授予与跳过教学的规则由 [成长规格](05_PROGRESSION_AND_SAVE.md)负责；
跳过教学不应使档案陷入没有艇、没有钱、无法执行任务的死局。

## 4. 港口与出航

港口中央展示当前艇，玩家能直接查看型号、战术侧重和配装；旁侧提供行动入口。
不做可以步行的港口，不把静态收藏展厅当作拥有舰艇列表。

出航顺序建议：选择任务 -> 阅读已知情报 -> 检查任务约束 -> 调整合法配装 -> 确认出航。
任务简报给出目标与情报来源，不透露未探测敌人实时坐标、状态或精确行动路径。
确认后冻结任务参数、选艇和配装；战斗中不通过港口菜单修改能力。

失败的出航验证返回具体原因，例如任务要求未满足、必需数据缺失、存档不可写。
任何失败都不得扣除资源、生成半个会话或留下仍在运行的仿真。

## 5. 单局体验

| 阶段 | 体验设计 | 防止的问题 |
|---|---|---|
| 开场 | 出现在合理接敌距离，有简短目标和环境信息 | 用长途无事航行冒充真实感 |
| 搜索 | 被动接触先给方位与不确定性，航行选择改变监听条件 | 默认精确红点消灭信息博弈 |
| 占位 | 玩家权衡速度、噪声、拦截窗口与安全深度 | 所有艇都用相同最优操作 |
| 攻击 | 选择目标、武器、预计路径与发射时机，明确无解算原因 | 单纯等待“百分百命中”按钮 |
| 反扑 | 护航依据获得的情报搜索；威胁通过可观察报告呈现 | 发射后敌人瞬移或全知追踪 |
| 收尾 | 主要目标后明确提示可撤离，继续攻击是额外风险 | 必须清空全图或无期限寻找残敌 |

视图分为世界跟随、战术图、潜望镜；三者共享同一公开信息边界。声音也受同样约束。
操作允许暂停；标准玩法不要求手算所有火控。帮助系统解释拒绝原因，不代替玩家决定战术。

## 6. 胜负、撤离与复盘

- 任务分别定义主要目标、可选目标、撤离条件和明确失败条件，不统一使用“全灭”。
- 主要目标完成不等于会话立即结束；需要撤离的任务应保留离开战场的最后决策。
- 玩家艇毁损、任务必要目标失效等由仿真确认；退出到桌面不是新的战斗胜负事实。
- 结果页先显示任务结果及原因，再列关键事件与研究收益，不以击沉数掩盖目标失败。
- 复盘展示来自事件日志的事实与时间；未记录的敌方动机不得以确定语气补写。
- 允许重试或返港；同一场结果重复打开不再发奖励。

首发建议不提供全知敌方轨迹回放，减少信息泄露与复盘系统的额外制作量。

## 7. 成长与任务难度

采用研究点一种成长资源的方向；新艇和配装由真实合法候选构成。
研究界面显示差异和取舍，不将真实型号声学性能的推测值包装为实测排名。

难度来自已声明的敌方编制、环境、目标约束和反应参数，不在战斗中偷偷读取玩家表现
增加敌军或强化探测。不同难度仍使用同一信息权限和公平性原则。
新艇不让旧艇失去所有用途；侦察、近岸伏击和长距离追踪可强调不同能力。

## 8. 游戏结束后的继续游玩

主行动完成后可重玩任务及其经验证的固定种子变体，保留最高评价与研究进度。
不以真实日期刷新内容，不设置体力或每日登录；首发不要求开放世界和动态战争系统。
任务变体改变编队、入场方向或天气组合，但必须保持可完成性和简报的一致性。

## 9. 首个切片必须证明的体验

- 不看文档的新玩家可以进入任务，理解一条接触不是精确目标。
- 至少有两种可行决策路径，不是唯一脚本答案。
- 发射后敌方反应和脱离过程可被观察、解释和重试。
- 胜利、失败、主动退出、暂停继续和重新载入均有明确状态。
- 返港获得一次合法研究机会，研究结果保存并改变下一次出航的能力。

这些验收先于六艘艇、更多任务、精细特效和 Steam 商店展示。

## 10. 完整会话状态表

这是新会话协调层的逻辑状态，不直接改写现有 `ESDGameState`。状态映射和迁移须通过接口评审。

| 状态 | 允许的操作 | 正常下一状态 | 失败与取消 |
|---|---|---|---|
| 启动检查 | 退出、查看错误 | 无档进入初始设置，有档进入港口或恢复选择 | 损坏档进入恢复页；必需配置缺失停在错误页 |
| 初始设置 | 应用、退出 | 首次档案提交后进入教学选择 | 写入失败保留设置页；不授予半份初始资源 |
| 恢复选择 | 继续活动任务、明确放弃、退出 | 继续则装载，放弃则提交中止后港口 | 不兼容活动任务只允许保留档案并放弃该任务 |
| 港口 | 行动、研究、配装、设置、退出 | 简报、研究详情、配装 | 未保存的事务错误仍留港口，不允许并发出航 |
| 简报 | 返回、调整配装、出航 | 出航准备 | 约束不满足则定位装位；不扣资源 |
| 出航准备 | 取消 | 内容验证和任务初始状态提交后装载完成 | 取消或装载错误使本实例作废，不占活动任务槽 |
| 战斗 | 合法命令、暂停 | 暂停或唯一终态 | 资源故障进入暂停错误，不把异常判为胜利 |
| 暂停 | 继续、设置、保存退出、中止确认 | 战斗、保存或中止结果 | 返回保留暂停；不会自动恢复仿真 |
| 保存中 | 查看进度 | 成功后返回原状态或退出 | 写失败保持暂停，可重试或明确放弃本次保存退出 |
| 结果待提交 | 查看结果、重试保存 | 提交成功进入战报 | 不允许研究、重试任务或再次结算 |
| 战报 | 港口、再次出航、查看事件 | 港口或经过相同验证的新实例 | 再次出航失败仍留战报，原奖励不重复 |

## 11. 中断、退出和中止的区别

- 失焦、系统挂起、Steam 覆盖层打开和控制设备丢失统一请求暂停；恢复窗口后仍暂停，清空边沿输入。
- “保存退出”在完整 tick 边界冻结并保存活动任务，重启可继续；成功保存后才结束进程。
- “中止任务”是玩家确认的终态，保留既有拥有权，结束本场；没有失败惩罚性维修费。
- 关闭窗口等同退出请求，先走保存流程；操作系统强杀无法保证保存，重启回到最近有效检查点。
- 战斗结果已经冻结时，退出只触发结果持久化，不把胜利改为中止；写失败使用恢复协议。
- 不支持主动放弃保存后仍保留未提交收益；提示明确说明将回到最近的有效记录。

暂停是会话控制而非游戏内能力；任务时间、鱼雷、敌舰和声呐衰减全部冻结。
渲染资源异步装载和本地写盘可以继续，但不能产生新的战斗事件。

## 12. 重试与复玩的一致性

“重试本场”复用任务版本、种子、初始艇与冻结配装，但使用新实例 ID，全部战斗状态重置。
“再次出航”同样复用上次任务参数，必须重新核验当前拥有权与内容版本；配装想改变就先返港。
“选择变体”只在简报使用明确种子选择，不按真实时间生成。标准首次通关进度由任务 ID 记录。
重试不恢复上一场消耗的中间状态，也不把上一场的临时接触和敌方记忆带到下一场。
