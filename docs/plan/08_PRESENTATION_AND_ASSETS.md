# 视听表现与资产接入

版本：0.2；日期：2026-09-14；性质：新产品表现、资源预算与接入规格提案。
实际导入、视觉和性能均需单独验收，不从资产清单或旧截图推断成功。

## 1. 视觉定位

潜艇和海洋是画面主体：艇体材质有可读的形状与湿表面反射，水面环境提供距离和方位感。
避免把整场战斗做成不可辨认的黑屏，也避免通过发光轮廓暴露水下敌人。
界面采用克制深灰底、清晰浅色文字和少量青色交互强调；琥珀与红色用于告警，不能只靠颜色传意。
界面色值与尺寸已在界面规格 §15 给出；材质、后处理仍须真实编辑器验证，不等于 UMG 美术稿已交付。

## 2. 视图各自的任务

| 视图 | 主要用途 | 限制 |
|---|---|---|
| 世界跟随 | 本艇操纵、海洋尺度、运动和武器反馈 | 只表现公开实体；不为电影镜头选择隐藏目标 |
| 战术图 | 估计接触、方位、航路和任务区域 | 位置不确定时使用线/区间，不伪装真实小地图 |
| 潜望镜 | 窄视野光学观察与战术暴露取舍 | 视场、遮挡、升降状态由契约约束 |
| 港口 | 当前合法艇与配装观察 | 不同时装载整座资产库，不混淆收藏与拥有 |

海浪、姿态摇摆和潜艇可动件动画仅表现，不改变深度、声呐命中、碰撞或任务条件。
相机切换不能授予新情报；可见性撤销应同步清理尾迹、灯光、标签与声音线索。

## 3. 音频方向

| 声音 | 玩法用途 | 权限来源 |
|---|---|---|
| 本艇推进与机械声 | 感受速度、自噪和受损状态 | 本艇公开状态 |
| 被动接触报告 | 告知新接触、分类变化和失联 | 授权接触事件，不直接播放隐藏敌舰空间声 |
| 主动声呐与入射 | 表达主动探测和被他方探测的可观察迹象 | 已公开传感器事件 |
| 武器、近爆与损伤 | 表达危险与影响 | 本艇实际听到/受到的事件 |
| 界面与港口环境 | 操作确认与环境气氛 | 非权威界面状态 |

程序化音频或本地录制均可，选择依据是质量、许可和成本，不受旧 WebAudio 实现约束。
声部设上限、优先级、重复抑制与释放策略；长循环在退出任务后停止。
语音不是首发必需条件；关键报告同时提供可读反馈，支持分组音量与字幕。

## 4. 首个任务资产需求矩阵

“候选”意味着需要检验，不能在表格里自动标为已就绪。

| 资产组 | OP-001 最低需要 | 当前处理建议 | 验收 |
|---|---|---|---|
| 玩家艇 | 1 套艇体、可动件、相机与发射挂点 | 优先核验 Akula 现有路径 | 尺寸、轴向、LOD、挂点、材质与动画 |
| 运输目标 | 1 类目标舰可见外观与受击/毁损表现 | 先盘点现有本地资源，不假设已具备 | 合法来源、尺寸、碰撞代理与毁损事件对应 |
| 护航舰 | 1 类水面护航舰与必要武器表现 | 缺少时只在开发期使用受控程序化外观 | 出场、搜索反馈、攻击和清理 |
| 鱼雷与诱饵 | 各 1 个有效类型的显示资产 | 从已登记本地库选择 | 发射挂点、方向、生命周期和可见权限 |
| 海域 | 1 套海面、天空、离线海域数据 | 复用当前海洋场景并验证 | 海天曝光、水下可读性、数据与表现对齐 |
| 港口 | 单艇观察场景 | 从海洋资源构成轻量场景，不先建可漫游基地 | 选艇切换、装载和释放 |
| 音效和特效 | 声呐、发射、近爆、受损、结果反馈 | 本地素材或程序化制作 | 授权、事件映射、字幕、资源上限 |

正式版本不得保留仅用于调试的资产或误导外观。程序化外观只有达到批准的正式质量标准，
才能作为首发资源；可选资源故障的程序化回退仍需保留并验证。

## 5. 资产治理

- `SilentDepth_Assets/` 继续是源资产唯一权威，UE 的生成数据副本走既有同步脚本。
- 手写平台、socket、装备效果与研究成本配置不当作生成文件覆盖。
- 母版只读与工作副本流程沿用 [模块化资产管线](../SUBMARINE_MODULAR_ASSET_PIPELINE_PLAN.md)。
- 新资源记录本地路径、来源、商用许可、SHA-256、LOD/三角面、材质与贴图规模和平台引用。
- 审计通过、导入通过、可玩接线、编辑器观察分别记录，不以一个“完成”字段混合。
- 历史文件哈希不匹配必须先查实际变化；不能无条件重新生成哈希消掉错误。
- 全部必要资源随游戏包交付，不使用 CDN、远程字体、贴图或首次启动下载。

## 6. 表现预算与质量档

目标硬件尚未确认，不继承旧文档中的帧率、显存或三角面上限作为已证实指标。
第一轮实测应分别测港口、正常接敌、最多公开实体、武器与近爆高峰场景。

待实测建立的预算包括：CPU/GPU 帧时间、显存、系统内存、加载时间、公开舰船数、
粒子与声音池容量、临时灯光、材质实例、接触历史和事件积压。
渲染质量档只改变视距内的表现成本，不改变声呐范围、敌方可见性规则或伤害。
场景曝光和水下后处理必须在真实编辑器编译观察，UBT 不能证明材质结果正确。

## 7. 验收

ART-001：首个任务资产路径、许可、哈希、平台/装位引用完整且检查通过。
ART-002：在 UE 中观察水面、水下、潜望镜、港口，检查尺度、方向、材质和文字可读性。
ART-003：同一隐藏目标对比有/无场景时，不产生模型、尾迹、光源或未经授权的声音线索。
ART-004：连续重开、切艇、返回港口后资源不持续增长；记录对象数与内存，不凭观感判断。
ART-005：包内资源缺失时，必需能力拒绝出航，可选外观合法回退；不改变研究或战斗结果。

## 8. 初始容量与性能目标

以下是工程限额与测试目标，不是当前实测结果或商店最低配置。超过限额应优化/调整数据，
不能静默删掉权威舰船、武器或接触。实际目标硬件由 GAME-023 指定后再测量。

| 项 | 初始上限/目标 | 超限处理 |
|---|---|---|
| 单场舰船/潜艇 | 16 个权威实体 | 任务装载拒绝；不按镜头距离删除敌人 |
| 在航鱼雷/诱饵 | 64 / 32 | 发射前权威容量检查；拒绝不扣库存并记开发诊断 |
| 每观察者接触 | 64 | 先陈旧，再按最后观测时间从旧到新、ID 升序淘汰；不越权改选真目标 |
| 活跃声音 | 48 | 本艇危险与近爆优先，环境声让位；不能丢唯一的危险反馈字幕 |
| 瞬时特效实例 | 128 | 合并重复环境反馈，危险事件保留简化表现 |
| 临时局部灯光 | 4 | 按已公开危险事件优先级复用，生命周期最长 2 秒 |
| 可读短日志 | 5 行，每条 6 秒 | 完整公开日志可在暂停查看，最多 512 条 |
| 港口驻留展示 | 当前艇加一个预加载候选 | 换艇销毁旧独占资源，不装载整个艇库 |
| 中画质 1080p 目标 | 60 帧；95% 帧时间不高于 20 ms | 仅作为具名设备上的优化目标，不据此宣布达标 |
| 任务装载目标 | 常规海域 30 秒内 | 记录冷/热启动和设备，超时不给虚假百分比 |

接触容量淘汰本身属于公开接触生命周期规则，必须在 Core 执行并产生接触移除事件；
不能让 HUD 因容量丢一条后仍在火控中使用未呈现的接触。已选中不免于依法丢失。

## 9. 外观降级矩阵

| 缺失/异常 | 允许的回退 | 禁止 |
|---|---|---|
| 非必需可动件 | 隐藏该部件并记录资产诊断 | 借用其他艇的部件和偏移伪装已接线 |
| 当前艇可选精细模型 | 经批准的程序化艇体与同一权威尺寸 | 改成另一平台的能力或授予另一艇 |
| 必需发射位置/朝向 | 无；拒绝该配装出航 | 用模型中心猜发射口 |
| 特效/非关键声效 | 简化本地表现或静默，但保留授权 HUD 事件 | 影响命中/探测或泄露隐藏事件 |
| 材质编译失败/主字体缺字 | 阻塞该发布候选，开发环境用明确故障标记 | 用截图修饰而不修真实包 |
| 海底数据与可见地形错位 | 阻塞地图验收 | 让表现碰撞代替修正权威数据 |

## 10. 摄像机与视听时间

世界相机只跟随本艇公开姿态，环绕中心固定为本艇声明相机锚点；无隐藏敌人自动构图。
相机可用真实帧时间平滑，但移动速度不决定声呐/潜望镜授权视野。镜头碰撞只避开地形，
不得因隐藏舰船碰撞使镜头移位暴露它；水下镜头不显示未授权实体的轮廓、阴影和反射。
任务终态停止战斗音源，允许战报反馈；暂停保留低音量环境，武器循环不继续模拟移动。
用户关闭震动/闪光后仍有同一可读事件。恢复检查点只重建持续状态，不重放保存前全部爆炸。

## 11. 资产发布验收包

每个可发布资产附带：来源与授权、哈希、LOD 三角面、贴图尺寸、材质数、轴向/尺寸、
UE 路径、装配映射、错误回退策略、真实编辑器截图与所用引擎/机器。
开发生成水深数据同样有算法版本、参数和哈希，不因它没有模型就跳过治理。
资源台账将“已存在/已导入/可玩接线/编辑器观察/性能测量”分列；后四项必须附实际证据。
