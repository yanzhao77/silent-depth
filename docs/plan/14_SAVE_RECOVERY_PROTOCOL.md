# 档案事务、崩溃恢复与版本协议

版本：0.2；日期：2026-09-14；性质：GAME-032 的详细设计提案。
这是对现有单正式槽/临时槽实现的后续改进目标，本轮不修改代码或现有存档。
档案结构扩展前必须审查 [当前 schema](../UE4_TECH_TREE_SCHEMA.md)并补迁移，不能直接换格式。

## 1. 保护目标与明确限制

一次提交同时包含研究余额、拥有权、配装、统计、任务序号、活动任务和结算标记。
不存在“余额先写、任务标记后写”的分拆提交；成功确认只能发生在完整读回校验之后。
已经确认持久化的记录不能因新写入失败而损坏；尚未写成功的数据在强杀/断电后可能丢失，
系统只能恢复最近完整提交，不承诺保存故障后仍不丢任何未提交战果。
这不是防作弊协议；校验和防损坏，不把本地摘要说成可信服务器签名。

## 2. 持久化单元

采用两个完整提交槽 `Profile_A`、`Profile_B`，每槽包含同一个生涯档案与可选活动任务。
它们是 A/B 备份版本，不是玩家可选择的两份生涯。一个进程持有唯一写者锁；第二实例只显示
“游戏已在运行”并退出，不以只读游戏模式争用存档。磁盘写入串行，UI 事务不得并发覆盖。

每槽的最小信封字段：

| 字段 | 约束 |
|---|---|
| `formatVersion` | 不支持的未来版本只读拒绝；不得自动降级 |
| `profileId` | 创建档案一次生成的非玩法标识，不能参与 seed、RNG 或战斗判断 |
| `generation` | 严格单调递增，溢出则拒绝写入 |
| `parentDigest` | 上次有效提交摘要，识别分叉与迁移来源 |
| `payloadLength/payloadDigest` | 限制最大长度并验证完整内容，不读取未界定内存或路径 |
| `account/missionProgress/settings` | 当前权威长期状态，配置版本与合法 ID 校验 |
| `nextRunSequence/settledThrough` | uint64 单调序号；已结算与已放弃实例均纳入高水位 |
| `activeRun` | 空，或完整任务信息、快照、RNG、输入、结算阶段；只能一个 |
| `completeMarker` | 文件完整写入的结束标记；不是唯一有效性检查 |

活动任务的阶段只能是 `Reserved`、`Running`、`PendingResult`。
实例 ID 为 profileId 和本地递增序号，任务类型 ID 另存；设置不得改变活动任务规则指纹。
时间戳只用于用户展示，不用于选择较新档案或游戏裁决。

## 3. 提交流程

1. 从当前内存已提交版本创建候选副本，验证账户、任务、能力、序号和恢复状态全部不变量。
2. generation 加一，parentDigest 指向当前提交；序列化完整候选。
3. 写入非当前槽，保留当前槽不动；写入末尾完整标记并通过平台文件接口刷新。
4. 关闭后重新读取该槽，验证长度、摘要、版本、内容规则及 generation。
5. 只有校验全部成功才更新内存已提交引用并向 UI 确认；原槽自然成为备份。

“写 API 返回成功”不等于持久化验收通过。刷新与断电行为须在目标文件系统上做故障注入。
两槽都存在时不再额外维护一个可能损坏的“当前槽指针”文件；启动扫描槽自身决定。
异步写盘持有不可变副本和请求 ID，旧任务/关卡回调不能触发第二次事务。

## 4. 出航、检查点与结算

| 阶段 | 持久化内容 | 允许开始的动作 |
|---|---|---|
| 出航预留 | nextRunSequence 递增，activeRun=Reserved，冻结种子/任务/配装 | 资源准备，不推进仿真 |
| 装载完成 | 初始完整权威状态，activeRun=Running，tick=0 | 写成功后才开始战斗 |
| 自动检查点 | 完整 tick 末尾状态、全部 RNG 流、输入队列边界、目标谓词/计时 | 后台写失败不覆盖旧槽；游戏可继续并通知 |
| 保存退出 | 暂停后完整 tick 状态，清除未消费边沿动作，Running | 提交成功后退出 |
| 结果冻结 | 终态及结算输入、实例 ID，PendingResult；余额暂不变 | 仿真停止，只允许结果提交或错误恢复 |
| 奖励提交 | 账户/统计/首通一起变更，settledThrough=本实例，activeRun 清空 | 成功后战报、研究、再次出航 |
| 中止/装载取消 | 该序号作废并推进高水位，activeRun 清空；零收益 | 返回港口，后续使用新序号 |

每 60 仿真秒请求检查点；正在写时只保留一个最新待写候选，终态提交优先，不能越序完成。
任务结果到来先等待较早写操作完成，再提交 PendingResult；不能让后台旧检查点覆盖新结果。
检查点不是输入回放文件：必须包含航路索引、AI 搜索状态、观测缓存、鱼雷寻的记忆、冷却、
触底/越界/撤离计时、未来敌方命令与所有决定后续结果的数据。

## 5. 启动恢复表

| 发现状态 | 决定 | 用户反馈 |
|---|---|---|
| 无任何槽，且没有旧格式档 | 创建新档案流程 | 首次设置 |
| 一槽有效、一槽损坏/不完整 | 使用有效槽；保留损坏副本供用户诊断 | 告知已恢复有效记录 |
| 两槽有效，generation 不同，父子关系合法 | 选择 generation 较高者 | 正常继续 |
| 两槽同 generation、同摘要 | 等价，固定优先 A | 不重复发奖励 |
| 两槽同 generation、不同摘要，或不是预期同一档案链 | 不自动选择 | 显示分叉，允许导出副本后明确选一份 |
| 最高可见槽是未来格式 | 不绕过它自动回退到较旧代档 | 要求更新客户端，或用户明确选择回退并说明损失 |
| 两槽都损坏 | 不静默新建、不自动覆盖 | 导出诊断、退出、明确重置生涯三种操作 |
| 有旧格式且未迁移 | 按版本迁移表创建新槽，不改原文件 | 成功继续，失败仍可回旧客户端 |

校验包含原始摘要与语义，不接受“校验摘要相同但余额为负”之类记录。
因为文件系统或云服务可能产生分叉，不能只用修改时间或“研究点更多”选择。

## 6. 恢复活动任务

- Reserved：说明出航未完成；将实例作废并提交，再回港口，不重用其序号。
- Running 且版本/指纹支持：显示任务、检查点进度与继续/放弃；继续载入后先暂停，玩家确认才运行。
- Running 不兼容：保留长期档案；允许放弃本场并零收益返回港口，不假装换新版规则能精确续玩。
- PendingResult：不重新运行战斗；按被冻结结果和实例执行一次奖励事务，再显示战报。
- activeRun 序号小于等于 settledThrough：视为语义错误，不重新奖励；保留有效备份走恢复页。
- 同一实例的外部重复请求：返回已处理，不影响账户，不向 Steam 重复发送通知。

如果 crash 发生于奖励写入完成但 UI 尚未确认，启动会读到较高 generation 的已结算档案，
不能再次发奖。若发生在 PendingResult 写成功之前，只能回最后 Running 检查点。
恢复旧备份是完整档案回退，不将较新余额拼到较旧活动任务，以免产生重复收益。

## 7. schema 与内容升级

每个支持的旧 schema 有唯一迁移函数、输入样例、输出摘要和失败测试；逐版本执行，不跳过验证。
原档案保留只读备份，迁移在内存副本上进行，完整成功才写新格式。
未知平台/装备 ID 默认拒绝；只有版本迁移清单中明确声明的重命名/替代可以映射。
已拥有内容被移除时需发行决定：保留兼容数据或明确补偿迁移；不能由 UI 自行删除装备。
长期档案可迁移不代表活动任务可迁移；活动任务规则不匹配时明确要求放弃本场。
补丁回退只保证能读取该客户端支持的版本，不承诺新版档案能直接交给旧客户端。

## 8. 云存档候选功能

默认未启用，不创建上传代码或用户授权。若批准，上传仅包含完整的有效提交槽和必要元数据，
不上传日志、缓存、诊断、临时不完整文件或安装目录。
联网后同一链选择有效较高 generation；分叉必须在开局前由用户选完整一边，保留另一边副本。
活动任务进行中不热替换档案；检测远端变更延迟到退出活动会话的安全入口处理。
断网、超时、平台退出只停平台同步，本地保存继续；上传成功不能作为本地提交成功条件。
不支持跨设备同时游玩自动合并，必须在商店/帮助说明中如实表达。

## 9. 故障注入验收

SCN-061 至 SCN-074 覆盖提交和恢复；每一种写入都在创建文件、写一半、尾标记前、刷新后、
读回前、UI 确认前分别中断。用受控临时目录测试，不破坏真实用户存档。
预期始终是最近有效完整版本或明确恢复错误，不是“一切失败就新建一个档案”。
必须同时测试磁盘满、权限拒绝、旧回调晚到、后台检查点与结果提交竞争、未来格式和两槽分叉。
