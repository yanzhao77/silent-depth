# 测试、试玩与 Steam 发行

版本：0.2；日期：2026-09-14；性质：详细验收、运行异常与发行准备提案。
Steam 是已确认目标，但具体平台功能、售价、日期和公开操作尚未批准。
本文件不声称当前游戏已符合 Steam 审核、已取得商业授权或已通过发布验证。

## 1. 验证分层

| 层 | 要证明什么 | 不能替代什么 |
|---|---|---|
| 纯规则与数据检查 | 确定性、事务、schema、引用、合法边界 | 玩家理解、画面和性能 |
| UE 编译与 Automation | 当前 C++ 可构建、完整测试通过 | 材质编译、真实输入和打包资源 |
| 编辑器观察 | 实际界面、材质、相机、声音和交互 | 干净机器安装与目标硬件性能 |
| 发布包检查 | 无编辑器依赖、资源打包、路径权限、离线与保存 | 不同硬件都达标 |
| 具名硬件测量 | 帧时间、内存、显存和加载表现 | 未测设备的最低配置声明 |
| 人工试玩 | 学习成本、战术选择、失败归因和成长节奏 | 工程正确性或平台合规 |

## 3. 工程门禁

聚焦测试先行，完成代码改动后必须执行 UBT 和完整 SilentDepth Automation。
命令在仓库 [构建入口](../../README.md) 与 [代理规则](../../AGENTS.md)中维护，避免复制多套失效路径。
数据/资产相关改动同时执行 `npm run check:runtime-data` 和 `npm run check:asset-pipeline`。

记录提交、配置指纹、引擎版本、主机、命令、退出码和日志位置；Automation 必须是 0 失败，
并检查 `EXIT CODE: 0` 与测试队列正常结束。不得弱化测试以掩盖玩法差异。
材质/着色器、UMG 和相机需要真实编辑器观察；发布验证必须使用实际打包结果。

文档任务进行链接、术语、范围、决策状态和差异检查。没有执行 UBT/Automation 时明确披露，
文档检查通过不产生游戏功能的 `TESTED` 标签。

## 4. 试玩程序

第一轮建议邀请少量不同经验的玩家，例如 5 名；样本只用于发现问题，不证明市场需求。
不提前教完整操作，观察全新安装、教学、OP-001、失败重试、战报和首次研究。

| 记录项 | 方法 | 决策用途 |
|---|---|---|
| 首次有效决策时间 | 本地观察记录起步至理解一条接触 | 调整开场和教学节奏 |
| 任务时长与无决策等待 | 记录阶段时长及玩家解释 | 调整阵位和任务窗口，不用虚假加速隐藏缺陷 |
| 失败归因 | 询问“你认为这局为何这样结束” | 判断反馈是否足够、是否存在不公平感 |
| 再玩选择 | 不承诺额外奖励，观察是否愿意重试 | 判断单局本身的吸引力 |
| 升级理解 | 请玩家解释装备变化与下次打算 | 判断科技树是否提供真实选择 |

不自动上传玩家数据或启用遥测；记录和录像事先取得参与者同意。
与设计假设不符时更新问题和方案，不能编写“试玩证明成功”替代实际记录。

## 5. Windows 发布包验收

- 在没有 UE 编辑器和开发工具的干净 Windows 环境安装并运行，所需运行库随发行方案处理。
- 检查游戏默认地图、可用配置、资产软引用、字体、本地化和音频是否实际进入包。
- 标准用户权限、含空格与中文路径、只读安装目录下仍能保存到合法用户数据目录。
- 无网络条件执行首次进入、教学、任务、研究、退出和恢复，不依赖远程资源。
- 检查窗口模式、缩放、分辨率、音频设备切换、失焦与输入释放。
- 新档案、旧档升级、损坏数据、磁盘写失败、任务中断与结果重试都可解释并可恢复。
- 连续多局、返回港口与切艇不出现持续内存增长；记录测量，不凭短时运行下结论。
- 发布包排除开发探针、测试入口误触和源资产；调试符号另行保管以便崩溃排查。

最低配置与推荐配置只能由具名硬件实测支持。旧文档提到的显卡不是已验证的商店要求。

## 6. Steam 功能边界

| 功能 | 当前建议 | 接入前需要证明 |
|---|---|---|
| 商店与游戏包发布 | 发行必需工作，尚未执行 | 发行账户、应用配置、实际包、商店声明和当前官方流程 |
| 成就 | 候选，可延后 | 来源是已提交的合法本地事件；重复/离线重试安全 |
| 云存档 | 候选，优先保证本地可靠 | 文件范围、版本冲突、设备切换与离线恢复不毁档 |
| 完整手柄支持 | 待决定，不默认声明 | 所有页面、文本输入、设置、战斗和返回均可完成 |
| 创意工坊、多人成员服务 | 不在首发建议范围 | 另行产品与安全设计，不随 SDK 默认开启 |

Steam 集成不意味着核心游戏必须联网。平台故障应降级，不能阻止本地结果提交或改变仿真。
上传、公开商店、付款、签约和发售操作必须由用户明确授权，不由开发代理自行执行。

## 7. 商业交付检查

- 游戏名、图标、商店图、截图和预告片与实际发布版本一致；不使用未实现功能作卖点。
- 核对每项第三方模型、贴图、字体、音频、代码与插件的商用许可、署名和再分发条件。
- 单独核对真实型号名称、标识和第三方内容的使用风险；不把游戏数值包装成真实机密数据。
- 核对 Unreal 相关许可义务和届时平台要求；本文件不提供法律结论或固定收费信息。
- 确认语言、输入设备、存档、离线能力、系统需求与商店勾选项相符。
- 准备支持渠道、已知问题、更新说明、版本标识与可复现的错误报告格式。

## 8. 更新与发售后维护

每次补丁保留可识别版本、变更说明、配置指纹和存档兼容策略。
先在受控测试分支验证旧档升级和实际任务，再经负责人批准发布。
回退二进制不必然能读取新版存档；必须提前演练备份、恢复或明确拒绝，不能承诺万能回滚。
不在补丁中悄悄改变玩家拥有权或研究成本而不说明影响。

发售门禁包括：范围对应、核心回归、内容验收、发布包、性能、许可、商店一致性和负责人确认。
任何未验证项必须明确决定为阻塞、删减范围或公开限制，不能用“能启动”替代完整交付。

## 9. 场景测试执行协议

[场景矩阵](12_SCENARIO_MATRIX.md)的每一行是验收用例定义，不是测试通过记录。
执行证据包括：用例 ID、构建/规则/配置版本、初始档案/seed、步骤或输入文件、预期与实际、
退出码/事件摘要、截图或日志位置、测试者和环境。没有实际运行的状态统一为 `NOT VERIFIED`。
输入/状态/持久化必须能复现，不能只记录“点击后正常”。

首发必跑正常链、每条失败恢复路径与矩阵指定组合；候选功能关闭时验证入口不存在与本地流程不受影响。
候选功能批准启用后，平台测试从“不适用”升级为阻塞发布的必测项，不能继续借默认关闭跳过。
代码覆盖率不代替场景覆盖；场景数量也不代表所有参数组合或未知缺陷已被穷尽。

## 10. 发布包构建与交付物

使用当前 UE4.27 工具链制作 Win64 Shipping 发布包，Editor Development 包不能作为商店交付物。
BuildCookRun 的项目、平台、配置、Cook 地图集、Stage 目录、Pak 和运行库选项写入受控构建工单，
实际命令由该工作站验证后保存。不得在未运行时给一个硬编码安装路径盖通过章。
Cook 显式收集正式港口、任务地图、字体、本地化、数据与软引用资产；展厅和开发探针不默认打包。

一次发布候选至少保留：游戏包、文件哈希清单、应用/构建标识、所用引擎/代码/数据版本、
独立保管的符号、许可清单、配置迁移说明、已知问题、测试记录和回退方案。
干净机器验证已合法安装的本地包，无需安装 UE 编辑器或 Node；Steam 自身下载/授权流程
与游戏核心离线能力分开记录，不承诺在从未取得平台授权的环境绕过平台分发。

## 11. 运行环境异常

| 场景 | 处理 | 发布验收 |
|---|---|---|
| 首次离线运行已安装包 | 本地新档、教学和战斗可运行；无游戏自建账号登录 | 禁网实测，不仅断开 UI 状态图标 |
| 缺运行库/图形能力不足 | 安装器/启动诊断给出明确条件，不进入半个黑屏会话 | 干净机器与不支持配置各验证一次 |
| 安装目录只读 | 日志和档案写用户数据目录 | 标准账户，中文/空格路径 |
| 磁盘满/权限不足 | 保存失败，保留有效提交并提供恢复动作 | 注入故障，不删除真实用户档案 |
| GPU/渲染设备丢失 | 尽可能记录诊断并退出；下次安全显示启动，恢复最近有效档案 | 不承诺丢失设备后还能即时保存 |
| 音频设备拔出 | 切默认设备，失败则静音并保留字幕 | 不崩溃、不改变仿真 |
| 多开 | 第二实例拒绝启动写者 | 不能同时覆盖档案 |
| 睡眠/唤醒与失焦 | 暂停到 tick 边界，回来仍暂停 | 时限不按墙钟补走 |
| 系统强杀 | 下次依存档协议扫描完整槽 | 未提交进度可回滚，已确认提交不可混合损坏 |
| 安装/更新中断 | 平台恢复包完整性后再启动，缺文件停在错误页 | 不用残缺配置自动生成新游戏 |

## 12. 可选 Steam 功能的明确行为

默认不集成成就、云存档与手柄候选包；没有功能入口，不显示“正在连接”阻塞页。
若负责人批准启用，必须实现以下行为，而不是仅勾选商店特性：

- SDK 初始化失败：本地核心运行，平台能力不可用；不给失败付款或强制登录提示。
- 成就：只由已提交结果派发，以成就 ID 幂等；离线记录有限待同步集合，重复重试不反复弹提示。
- 云存档：使用存档协议 §8；完整版本冲突让用户选择，不按余额或墙钟合并，不在战斗中热替换。
- 覆盖层：打开请求暂停并释放鼠标；关闭仍暂停，等待玩家确认继续。
- 控制器：如果选择完整支持，全部页面必须能焦点导航；拔出暂停并显示键鼠可继续入口，
  重新连接不自动恢复发射/转舵。未选择支持时不宣称已支持或必须适配 Steam Deck。
- 平台用户切换：结束当前安全保存后返回启动检查，不把另一用户云档覆盖正在使用的本地档。

任何候选功能都不得向仿真注入时间、随机数、敌舰或收益；没有 SDK 也能运行相同回归序列。

## 14. 发售判定

玩法范围、全部首发内容、关键场景、安装/升级、许可、商店一致性和项目所有者确认缺一不可。

本轮文档审查不替代真实 UBT、Automation、编辑器、硬件、平台和法律检查。
