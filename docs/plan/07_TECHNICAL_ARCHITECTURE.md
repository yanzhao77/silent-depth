# UE4 目标技术架构

版本：0.2；日期：2026-09-14；性质：新产品唯一目标架构与接口提案。
架构红线沿用仓库规则；新增接口与会话实现为设计方案，不代表当前代码已满足。
本文件替代旧迁移架构作为入口，不新建并行的仿真或渲染管线。

## 1. 从现有模块渐进实现

继续以 `ue4/SilentDepthUE/Source/SilentDepthUE/` 为工程起点，先落实目录与所有权边界，
不为文档上的模块图立即拆分多个 UE 模块。现有 Core、平台能力、科技树、存档尽量复用。

```text
PlayerController / UMG 指令
    -> 会话入口 / 事务服务
    -> 唯一 C++ 仿真 -> Snapshot -> RenderState
                                   -> Actor / HUD / Camera / Audio / FX

会话入口 -> 科技树 / 配装 / 存档服务
可选平台适配 -> 本地提交后的非关键通知，不回写仿真
```

Snapshot 可含内部权威数据，仅适配边界访问。RenderState 为净化后的只读表现契约，
不包含可反查隐藏敌舰的指针或内部对象集合。

## 2. 所有权与生命周期

| 归属 | 职责 | 不允许 |
|---|---|---|
| 会话协调层，建议 GameInstance 生命周期 | 档案、选艇、任务装载、活动实例、状态转换、结束与返回 | 用 UI 行或 Actor 状态推断任务结果 |
| 唯一仿真入口 | 固定步累积、输入队列、Core 运行时、快照和事件批次 | 与 Pawn 同时各自推进一次仿真 |
| Core 纯规则 | 航行、传感器、敌方决策、武器、损伤、目标 | UWorld、碰撞回调、墙钟、平台 SDK 决定结果 |
| 数据与服务 | 装载校验、合法能力计算、研究、配装、存档事务 | 悄悄纠正非法配置或自动授予装备 |
| 表现层 | 插值、对象池、三视图、UMG、音频和特效 | 回写仿真、直接读取敌方真值 |

当前 Pawn 中的步进应在有回归覆盖的独立任务中移交。移交时保留同一航行函数，
先证明行为未被无意改变，再单独实现已批准的新核潜艇规则。

## 3. 拟定数据契约

以下为最小语义清单，不承诺已经存在同名类型。落地前查找并扩展现有合适模型。

| 契约 | 必需内容 | 生命周期 |
|---|---|---|
| 玩家命令 | 目标 tick、序号、命令类型、类型化参数、来源约束 | 消费一次；连续轴状态与边沿动作分开 |
| 任务会话 | 实例 ID、任务/规则版本、种子、配置指纹、冻结选艇与配装 | 装载成功至结果提交 |
| 快照 | tick、本艇、内部实体、接触、任务与待发布事件所需事实 | 仿真只读输出，不交给 UI |
| 表现状态 | 公开本艇、可见实体、估计接触、授权任务和 HUD 信息 | 仅显示；允许插值不允许产生新事实 |
| 事件批次 | 会话 ID、tick、稳定事件序号、类型化内容、公开权限 | 按序消费和去重，不在每帧重复播放 |
| 任务结果 | 实例 ID、唯一终态、目标完成、合法统计、结算输入 | 冻结后只提交一次 |

表现事件的可听、可见权限在产生时确定；不能在相机移动后重查隐藏世界并改变权限。
任务资源与弹药必须由能力契约独立定义数量语义，避免把发射管数当弹药总数。

## 4. 固定步与顺序

暂沿用 `FixedStep` 和现有 0.05 秒步长，卡顿采用有界追赶；不引入可变 dt 战斗路径。
只保存一个累积器。表现帧可以重复消费最近状态，但不能产生零时长仿真 tick。

拟定每 tick 顺序：

1. 按 tick 与序号消费输入，验证命令。
2. 更新环境和航行姿态。
3. 生成传感器观测，更新双方各自的接触估计。
4. 敌方根据本 tick 的合法观测产生下一 tick 命令。
5. 执行已验证的发射、武器运动、感知与碰撞计算。
6. 应用损伤，裁决任务目标与唯一终态。
7. 冻结快照、发布有序事件并生成净化表现状态。

本顺序是待实现契约；即时发射声学事件供下一次传感器步消费，避免隐含循环。
实体以稳定 ID 顺序更新，随机流用途固定；新增顺序需更新测试与规则版本。
地图坐标与 UE 坐标的转换沿用当前实现，经轴向与单位测试确认，不照搬历史文档另一套映射。

## 5. 输入、暂停和切场景

- 连续轴采样转为明确的固定 tick 输入；离散发射、诱饵等边沿仅消费一次。
- 暂停后不推进 Core、冷却、任务时间或随机流；UI 与必要声音可单独运行。
- 退出或切换关卡先停止输入并结束仿真拥有权，再释放订阅、对象池和控件。
- 装载任务失败时不进入战斗，关闭已创建的部分资源，保留上一个合法长期档案。
- 确认研究或配装走服务指令，战斗状态拒绝改装，不让 UI 直接写账户副本。

## 6. 确定性与兼容

使用现有 RNG 与命名派生，不为 AI、任务生成和音频增加第二个权威随机源。
同规则版本、配置指纹、初始状态/种子和固定 tick 输入应生成相同结果。
不同机器和构建的逐位一致性需要测试，不由“固定步”自动保证；首发先确定具名支持环境。
不再要求与任何 Web 输出相同。

长期档案 schema、任务数据版本、战斗规则版本和回放格式分别管理。
活动任务恢复必须保存完整所需权威状态和 RNG 流，不把 RenderState 当存档。
不兼容时保留档案并报错；平台云同步不能绕过版本和事务校验。

## 7. 资源与离线边界

必需资源装载失败关闭，可选外观按合法回退处理；回退不改变平台能力与所有权。
Actor、粒子、音频声部、接触历史、事件队列和材质实例有上限与清理路径。
暂停、重开、任务结束、返回港口和卸载分别有生命周期测试。
异步只做非权威资源准备；异步完成先后不得决定任务随机选择或实体更新顺序。

Steam 服务若获批，在本地结果成功提交后消费平台通知。Steam 不可用时不阻塞核心玩法；
本轮不新增 SDK、网络请求或上传逻辑。

## 8. 工程任务的最低交付

- 状态/命令/事件字段与所有权评审，含可公开信息清单。
- 核心单测、非法数据失败关闭测试、固定输入回放和暂停恢复测试。
- 静态依赖检查，确保表现代码不访问内部仿真状态。
- C++ UBT 与完整 UE Automation，通过后再做真实编辑器和发布包操作检查。
- 性能采样必须注明硬件、场景、版本、渲染设置和采样方法。

没有正式仿真与表现契约之前，不继续在 Pawn 或 HUD 内堆声呐、AI、战斗和任务权威逻辑。

## 9. 生命周期与会话接口语义

入口建议保持一个 GameInstance 级会话协调器，一个拥有 Core 的仿真服务，复用现有 TechTree 与 Save
子系统；不把下列概念名视作已经存在的 API。状态见游戏设计 §10，持久化见存档协议。

| 命令 | 输入 | 返回 | 幂等/取消条件 |
|---|---|---|---|
| PrepareRun | requestId、任务版本/种子、平台、配装指纹 | Prepared 或类型化错误 | 同请求返回同结果，取消后晚到装载不得重新激活 |
| StartPreparedRun | 已验证准备令牌 | RunId、tick=0 表现状态 | 初始 Running 档案提交成功才步进 |
| SubmitInput | RunId、targetTick、sequence、类型化动作 | 接受/拒绝原因 | 旧会话/重复序号拒绝，不投递到新场 |
| Pause/Resume | RunId、会话请求号 | 当前状态 | 重复暂停无效果；恢复必须是显式命令 |
| SaveCheckpoint | 不可变完整 Core 状态和版本指纹 | generation 或错误 | 串行，终态优先，不接受旧 generation 覆盖 |
| CommitResult | 已冻结的本场结果 | 已提交/已处理/错误 | 高水位与 activeRun 在同档事务里更新 |
| Abort/CancelLoad | 当前任务/请求身份 | 作废实例或错误 | 终态冻结后不允许改为中止 |

权威路径不接受任意 JSON 字符串、UObject 指针或隐藏实体选择作为输入；解析和验证在装载边界。
只读公开接触 ID 只能在该会话查找；找不到返回 SelectedContactUnavailable，不自动匹配最近敌舰。
标准内部错误类型包括 InvalidState、InvalidData、StaleRequest、UnavailableContact、
InsufficientPayload、IncompatibleLoadout、StorageFailure、UnsupportedVersion；UI 再映射本地化。

## 10. 时间、精度与输入队列

状态使用整数 tick；仿真连续量暂用现有 double。计算顺序固定，不承诺未经测试的跨平台位一致。
同支持构建下回放比较按规范化编码，不哈希含填充字节的 C++ 内存。字符串按 UTF-8，集合排序，
浮点拒绝非有限值并按稳定 IEEE 编码记录，不能让默认 JSON 库输出顺序决定指纹。
火控一次退化判断阈值为 `1e-9`，接触比较容差为 `1e-6 km`；命中排序将相差不超过 `1e-9 s`
的交点视为同时间再按 ID。边界容差不能放大成额外探测距离。

每帧非负时间累积上限 0.25 秒，每帧最多 5 次固定步，不补一次大 dt。
输入队列最多容纳 256 条，仅接受当前 tick 之后 1–5 tick 的命令；过载不静默丢发射，
拒绝请求并暂停会话显示本地输入错误。正常控制器只为下一 tick 编码，不用 UE 帧数做命令序号。
单个 tick 内输入采样固定后才开始更新；离散边沿按战斗规格消费，暂停清除尚未执行边沿。

## 11. 持久化、指纹与内容契约

任务规则指纹包含任务版本、种子、海域水深摘要、平台有效能力、武器/传感器参数和规则版本，
不包含纯表现贴图、相机、画质或语言。资产清单摘要另存用于装载诊断，不混同玩法恢复条件。
版本变更后不可恢复的活动任务明确拒绝，长期档案走迁移表；显示设置可独立回退不修改战斗指纹。
保存全部 RNG 流状态而不是仅 seed；保留关联历史与寻的滞回，避免恢复后首个采样改变目标。

正式任务数据最小字段：id/version、seaId/version、variant、seed、playerSpawn、spawns、routes、
objectivePredicates、extractRegion、timeLimitTicks、optionalGoal、rewardRuleVersion、localizationKeys。
每个出生实体必须有类型/稳定 ID/能力引用/合法位置，禁止凭资产名称猜武器、国籍或探测值。
schema 必须检查目标可引用实体、巡逻至少两个不同点、撤离区域可达、有限库存和非空主要目标。
对配置数值使用严格范围检查，不将不合法值自动夹紧成可玩的另一种任务。

## 12. 事件、队列与销毁

每事件身份为 RunId+tick+sequence；Adapter 按观察者权限产生可公开事件，事件不携带内部目标句柄。
事件批次每 tick 上限 128，表现待消费队列上限 1024；关键终态/伤害/库存事件不可因容量静默丢失。
超额属于开发错误，暂停并记录；仅重复的非关键表现反馈可以合并，核心事件完整保留。
已消费事件不因重建 UMG 或切镜头重放。状态型表现从最新 RenderState 重建，瞬时特效不追补历史。
退出顺序：停止接受命令 -> 完成/取消持久化流程 -> 解除事件订阅 -> 释放拥有资源 -> 销毁会话。
任务结果需要的纯数据可脱离 UWorld 保留；旧 Actor 的异步回调不可访问新的会话。

## 13. 可追溯验证

场景矩阵的 SCN-001 至 SCN-100 是规格用例，不是假造的 Automation 类。
每项实施须把相应用例映射到测试入口、固定输入/seed、期望事件与人工观察路径；
依赖倒置、C++ 类型与错误码测试和纯状态机测试在进入编辑器前执行。
