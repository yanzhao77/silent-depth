# 从当前代码到正式发售的开发路线

版本：0.2；日期：2026-09-14；性质：详细工单与验收路线，不是工期承诺。
起点见 [当前基线](01_CURRENT_BASELINE.md)；范围与授权见 [决策记录](11_DECISIONS.md)。

## 1. 排期原则

先建立一个可运行、可测试、可保存的完整体验，再扩展艇型与任务。
不先制作全部科技树界面，不按资产库数量排满首发内容，不同时实现所有现代武器。
阶段通过必须有工程证据和玩家操作证据；某系统有单测不代表整阶段通过。

依赖主链：产品决策 -> 基线与仿真所有权 -> 单局战斗 -> 返港成长 -> 内容扩展 -> 发布收口。
文档可以并行细化，但代码任务不得越过必要决策、契约和数据门禁。

## 5. 每个实施任务的标准工单

必须包含：对应需求、批准决策、代码入口、输入/输出契约、禁止触及项、配置和存档影响、
资源清理、聚焦测试、完整门禁、人工操作路径、证据位置、已知未验证项和回退方式。
一个工单不能同时跨越无关玩法重做、资产批量生产与商店公开发布。

代码任务结束报告列确切文件和命令结果；未执行验证不写通过。
提交仅在用户要求时进行；不把截图、大型生成物或其他用户工作自动纳入提交。

## 6. 停止扩产的条件

- 单局缺乏可解释选择，试玩主要时间是无决策等待。
- 隐藏信息通过镜头、图标或声音泄露；敌方表现为全知。
- 结算重复发奖、保存失败毁档或重开资源持续增长。
- 必需模型只有路径没有合法授权，或资产检查未通过。
- 核心战斗未稳定就用更多艇型、特效或研发节点掩盖问题。

出现这些情况先修复底层体验；不要通过扩大内容配额宣布进度。

## 7. 0.2 版工单输入与先后顺序

每张工单使用当前详细规格，不再让实施者临时决定“失败时怎么办”。
DEV-013 随 M1–M5 持续执行，不在代码完成后才编测试；DEV-014 按切片需要增量落地，
先一个海域/OP-001，再扩展完整目录。DEV-015 在 DEV-011 活动恢复最终验收前完成，
DEV-009 可先完成纯事务规则但不能提前宣布故障恢复已经安全。

| 阶段 | 必需场景范围 | 同时必需的非场景证据 |
|---|---|---|
| M0 | 规格链接、编号、参数算术和内容 ID 检查 | 用户决策、数据漂移处理、Windows 构建基线 |
| M1 | SCN-031 至 SCN-040、SCN-047/048 的基础规则 | 唯一步进、公开信息契约、三视图观察 |
| M2 | SCN-021 至 SCN-030、SCN-041 至 SCN-050、SCN-059 | OP-001 实际胜负/中止、资源生命周期 |
| M3 | SCN-001 至 SCN-020、SCN-051 至 SCN-084 | 新档全流程、UI 稿与真实控件、保存恢复与 COM-01/02/03/04/08 |
| M4 | SCN-045、SCN-046、SCN-085 至 SCN-090、COM-06/07 | 全任务变体校验、入门艇可通关、经济路线与角色差异 |
| M5 | SCN-091 至 SCN-100，候选开启时对应全测 | 干净包、具名硬件、许可、商店一致性与 COM-05 |

表中的阶段重叠表示必须回归，不是只在最早阶段测一次即可。
没有选择云等候选功能时，测试默认关闭状态；不能把未实现候选功能混进发布演示。

## 8. 任务完成的证据模板

工单完成记录：任务编号、规格/决策版本、改动文件、数据指纹、实际运行命令与退出码、
对应 SCN/COM 的结果、编辑器截图/日志、硬件与质量档、失败问题和未验证项。
代码存在只标 `IMPLEMENTED`；相关自动化通过可标 `TESTED`；真实编辑器与目标硬件分别追加各自标签。
文档结构校验通过只表示本轮文字与引用一致，不能把 M0–M6 全部标为通过。

后续新发现的问题新增 SCN 编号，不重新使用已删除编号；修规则同步测试预期与版本说明。
