# SILENT DEPTH V2.2 Asset & Cinematic Visual Upgrade Specification

**文档性质：** 实施规范，不是代码变更。  
**适用基线：** V2.1 已有的 `GameSnapshot → RenderState → renderer` 单向架构、Three.js 渲染器、质量预设、天气分类、事件类型、潜望镜和战术叠层。  
**硬性约束：** 不修改 Simulation Engine、AI、任务、声呐规则、数值平衡、存档和核心玩法。所有新增呈现元素只能消费 `RenderState` 及其视觉事件。[1]

## 1. V2.2 的主视觉目标

V2.2 的目标是一种**冷峻、克制、可被战术判读的电影化海军模拟视觉语言**。玩家应感到自己是在一艘小而沉重的潜艇上观察辽阔、危险、低能见度的大海；“漂亮”必须来自湿润钢材、海面反光、云底、月光、雾、航迹和舰影之间的关系，而不是饱和色、常驻发光边框或后期噪点。

在正常世界视图中，玩家潜艇应是构图锚点，但不应始终占满画面。最常用镜头采用左后上方的三分之四跟随：近距能读出艇桥、舵面、舷侧细节与螺旋桨扰流；中距能读出航向、速度和深度；远距让海况和舰影承担压力。夜间仍保持暗部主导，但月径、舷灯、火光和泡沫必须给出有限且可信的判读机会。

> **体验准则：** “先看见海，再看见舰影，再获得信息。” 视觉叠层应解释不确定性，而不得替代侦察。

| 视觉轴 | V2.2 目标 | 明确禁止 |
|---|---|---|
| 色彩 | 冷蓝灰、湿黑、低饱和钢绿；只将黄/红用于警告与威胁。 | 霓虹青边、赛博紫、全屏高饱和 LUT。 |
| 光照 | 强方向性主光 + 弱环境反射 + 少量剧情性局部光。 | 满屏平均照亮、无来源的环境泛光。 |
| 海面 | 远涌、中浪、近景微面与可读泡沫分层。 | 规则条带、单频波浪、平铺纹理感。 |
| 资产 | 少量高价值 hero asset + 远距降级版本。 | 每种单位都追求近景电影级面数。 |
| UI | 边缘化、情境化、随模式收纳。 | 以常驻说明、卡片和滚动日志遮挡世界。 |
| 电影化 | 轻量模式转场、稀疏事件镜头、可跳过。 | 持续摇晃、长时间夺取控制或强制播放镜头。 |

## 2. V2.2 资产策略：混合而非全盘替换

现有资产管线将全部资源视为 CC0 程序化资产，并由 `assets/registry.json` 及测试维护完整性。[2] V2.2 不应删除这套低成本、离线友好的基础；应将它扩展为“**程序化效果/远距占位 + 可追溯 PBR 材质 + 经过许可闸门的 GLB hero asset**”。程序化资产继续负责海面、雾、声呐圈、粒子、HUD 和远距单位；只有潜艇、2–3 类关键敌舰以及少数高价值道具需要升级为模型/贴图资产。

### 2.2 资产分层、格式与预算

英雄资产质量由**轮廓、PBR 分区、法线细节与受光表现**决定，不由无限面数决定。当前代码的潜艇和舰船可保留为 `LOD2` / 故障回退：这样离线演示和低档位仍有完整单位覆盖，且不会破坏现有模拟单位类型。

| 资产层 | 单位范围 | 三角面预算 | 纹理/材质预算 | 交付格式与运行规则 |
|---|---|---:|---|---|
| Hero LOD0 | 玩家潜艇、被锁定/近距驱逐舰、近距货轮 | 潜艇 25k–45k；舰船 18k–35k | 每类最多 2 组 2K KTX2 材质；每组 BaseColor + Normal + ORM | 单一 `.glb`，KHR_mesh_quantization + Meshopt/Draco；距离 < 0.35 km 时载入。 |
| Standard LOD1 | 一般可见舰船 | 4k–10k | 1 组 1K KTX2，或合并材质图集 | 优先同一 geometry/material 复用；距离 0.35–1.5 km。 |
| Far LOD2 | 远距船团、潜艇、背景物 | 300–1.5k | 256–512 px 图集或程序化材质 | `InstancedMesh` 或现有程序化组；距离 > 1.5 km。 |
| FX / decal | 尾迹、泡沫、爆炸水花、湿痕 | Quad/strip 为主 | 256–512 px KTX2；图集化 | 所有特效对象池化，生命周期结束即回收。 |
| UI / 光学 | 潜望镜环、刻度、坏天气污渍 | DOM/Canvas 优先 | SVG 或 512 px 透明 PNG/KTX2 | 不把文字或仪表制作成高面数 Three.js mesh。 |

**纹理内存门槛。** High 档 hero 静态纹理预算为 48 MiB，环境/HDRI 12 MiB，FX/UI 12 MiB，合计不超过 72 MiB 的压缩 GPU 纹理常驻目标；Medium 为 36 MiB，Low 为 20 MiB。内存估算、网络传输大小和解码后 GPU 占用必须分别记录，不得用压缩包大小替代 GPU 预算。

### 2.3 扩展后的资源注册表

在真实外部资产进入前，先将当前仅接受“所有条目均 procedural + CC0”的测试扩展为**逐条许可闸门**。变更后的注册表仍以本地相对路径为唯一运行时路径；运行时先校验 hash，再加载资源。建议新增的 V2 字段如下。

| 字段 | 要求 |
|---|---|
| `id`, `name`, `type`, `path`, `sha256` | 保持现有稳定标识、本地路径与最终交付文件哈希。 |
| `sourceKind` | `procedural`、`external_cc0`、`external_cc_by`、`commercial` 之一。 |
| `sourceUrl`, `assetPageUrl`, `author` | 三者不可为空；程序化资产用仓库路径和作者。 |
| `license`, `licenseUrl`, `attribution`, `licenseCheckedAt` | 实际页/文件证据；CC BY 必须有可展示署名；未知即阻断。 |
| `originalFilename`, `originalSha256`, `processedBy`, `processCommand` | 保留来源文件与处理可复现性，防止优化后无法追溯。 |
| `format`, `lod`, `triangles`, `textureSet`, `compressedBytes`, `gpuBudgetBytes` | 让审查和性能预算可自动检查。 |
| `reviewStatus`, `reviewedBy`, `notes` | `approved` 才能被打包；记录比例/风格、品牌、商标风险。 |

## 3. 电影化渲染规范

### 3.1 潜艇与舰船

玩家潜艇使用一个具备明确耐压壳/甲板、艇桥玻璃、桅杆、舵面、自由排水孔、鱼雷口、螺旋桨和可选水面状态细节的 hero asset。材质拆为船壳漆面、甲板防滑、玻璃/光学、黄铜/钢制细件和橡胶五类。金属度不应把全艇涂成镜面：湿润感主要来自 roughness 变化、波峰反射和受光角度。不得把环境色烘焙进 BaseColor。

舰船遵循“剪影优先、识别次之、细节最后”。Destroyer 的前甲板炮、上层建筑、桅杆与烟囱应构成高窄轮廓；Frigate 应有机库/直升机甲板和雷达；Cargo 应有重复但不规则的箱体节奏；Tanker 通过低长甲板、管线与后部居住区区分。夜间远距舰船首先是黑色质量与稀疏航行灯，而不是高亮可见的模型。

| 行为 | 呈现规则 | 可用视觉数据 | 禁止项 |
|---|---|---|---|
| 潜艇速度变化 | 螺旋桨转速、船尾扰流、镜头滞后和泡沫随 `speedKt` 连续变化。 | `player.speedKt`、朝向、位置。 | 向仿真回写阻力、噪声或浮力。 |
| 潜望镜升降 | 0.35–0.5 s 阻尼，伴随细微镜头抬升、湿润反光和 UI 收纳。 | `periscopeState`、camera mode。 | 伪造接触确认或改变曝光规则。 |
| 可见敌舰 | `ship.visible` 决定实体显示，接触椭圆只代表估计。 | `ships`, `contacts`。 | 用接触分类提前显示精确模型。 |
| 破损 | 仅使用现有 `hull`、视觉事件和局部烟/火/倾斜 cue。 | `hull`, `effects`。 | 创建新的伤害数值或燃烧状态。 |

### 3.2 海面、天空与天气

当前海面已经具备 GPU Gerstner 波和天气参数；V2.2 保留这一方向，但把画面组织成三层。远景只保留低频涌浪、雾和地平线；中景增加两组交叉风浪与分布式破波；近景通过视角依赖高光、低频法线滚动和稀疏泡沫遮罩表现微面。船只/潜艇尾迹采用沿速度方向展开并渐隐的 ribbon/decal，头浪、船尾涡流和转向尾迹使用不同的粗糙度与寿命曲线。

天气必须是一个包含视觉因果关系的 preset，不应只是换 RGB 值。风向同时驱动波向、雨线倾角、烟/雾漂移和尾迹偏移；云量同时影响天空亮度、漫反射与月/日光路径；能见度同时约束雾密度、远距 LOD 和远景 detail。雾使用两层：世界指数雾保证性能与远距退场，低层海雾 billboard/体积近似提供地平线层次。

| 预设 | 视觉身份 | 必须呈现 | 避免 |
|---|---|---|---|
| Clear / M01 | 冷亮晨光，远处可读地平线。 | 窄而长的日光水径、低云稀薄、浅色泡沫。 | 过暖旅游海报色。 |
| Cloudy / M02 | 平直、压抑、对比度低。 | 厚云底、弱高光、钢灰舰影。 | 均匀灰幕导致无层次。 |
| Fog / M03 | 近距信息可信、远距不可信。 | 海雾高度带、前后景色温差、舰影渐出。 | 用单纯 alpha 让所有物体一起消失。 |
| Storm / M04 | 方向性强、短时高对比。 | 斜雨、浪雾、破波、偶发闪电的局部曝光。 | 每帧更新 4,000 CPU 粒子。 |
| Night / M05 | 几乎不可见，但必须可判读。 | 月径、远距微弱灯点、泡沫边缘、黑色舰影。 | 全黑或青色夜视滤镜。 |
| Deep / 所有关卡 | 冷、浑浊、向下吸光。 | 深度色散、悬浮微粒、局部泡沫/气泡、远景压黑。 | 高频焦散、蓝色泛光和过亮玩家模型。 |

### 3.3 事件特效与镜头

特效必须按阶段工作，且让玩家判断后果。鱼雷发射包含发射口白水/气泡、短暂尾迹与远去声呐线；命中包含水柱起始、局部火光/烟、冲击环和可读的舰体受损 cue；深水炸弹包含下沉泡迹、深水闷闪、上涌气泡与短促相机低频震动。当前 `RenderEffect` 已给出 sonarPing、torpedoWake、explosion、waterSplash、depthCharge、shipWake、bubbleTrail 的视觉事件域，V2.2 的 Visual Director 只能在该域内编排。[1]

相机以操控稳定优先。世界 → 潜望镜使用 0.35 s 轻微上仰、暗角/遮罩淡入；潜望镜 → 战术使用 0.25 s 偏焦/降饱和后切到正交海图；鱼雷和命中事件可提供不超过 1.2 s 的“建议式”观察镜头，按任意输入或设置立即跳过。严禁在转向、瞄准和火控过程中强行夺取相机。

## 4. HUD、潜望镜与战术信息规范

世界视图的常驻 HUD 只保留深度、速度、航向、被探测警告、鱼雷/诱饵剩余数和最重要目标状态。控制清单、长事件日志、完整接触名单和设置移入可展开抽屉。默认 16:9 下 HUD 的高不透明区域不超过可见画面面积的 20%；右侧信息栏最多 30% 宽度，出现交战/锁定时自动压缩。

潜望镜模式以圆内世界为主。圆外整体降至约 25% 不透明度，仅保留“深度、航向、曝光/升起状态、锁定状态、退出提示”；圆内只显示方位、最短距离/类别线索和锁定 brackets。现有圆环、密位、方位、凝结和水滴可保留，但水滴应为低频、带有尺寸分布且只在风雨/上浮状态增加。目标标签先于实体不可见时必须保持“接触估计”的语义，不得把分类文本贴在完整精确船模上。

战术层保留当前椭圆、置信度、状态色、声呐环、航迹和鱼雷路线，改为距离/置信度驱动透明度与标签密度。接触升级时改变椭圆形状、线宽和短暂辉光，而非闪烁大图标。主动声呐只能增加“回波证据”，不可将所有目标立即重绘成确定敌点。

## 5. 性能、加载与降级规范

V2.2 的美术复杂度必须从预算开始，而不是在画面完成后再删。浏览器中将 High/Medium/Low 视为完整产品档位：Low 仍保留潜艇、舰种、雾与关键事件，只削减远距 LOD、纹理分辨率、海面分段、雨密度、阴影与屏幕后期。

| 指标 | High | Medium | Low | 验收方式 |
|---|---:|---:|---:|---|
| WebGL draw calls | ≤ 120 | ≤ 90 | ≤ 65 | 性能面板/帧捕获；列出 top 10。 |
| 可见动态特效实例 | ≤ 180 | ≤ 110 | ≤ 60 | 对象池计数，不累计泄漏。 |
| 近场雨滴/雨线 | ≤ 1,200 | ≤ 700 | ≤ 250 | GPU `Points` 或实例化 quad，禁止逐帧 CPU 全量位置循环。 |
| 海面分段 | ≤ 256×256 | ≤ 160×160 | ≤ 96×96 | 质量预设日志与截图。 |
| 主纹理分辨率 | 2K | 1K | 512 px | KTX2 加载日志和 GPU 估算。 |
| 目标帧时间 | ≤ 16.7 ms | ≤ 25 ms | ≤ 33.3 ms | 在代表性真实 GPU 的 M04/M05 峰值场景采样。 |

加载时先显示程序化 LOD2 和可交互 HUD，hero GLB/贴图异步替换；任何失败均回退到现有程序化资产并上报具体 registry id。每个任务结束必须 dispose geometry、material、texture、render target 和对象池借用实例；切关 10 次后的 GPU/JS 内存不得单调增长。不得将受控浏览器约 6.7 FPS 的采样当作发布性能结论。

## 8. Definition of Done

V2.2 视觉工作完成，必须同时满足下列条件：所有外部资产有逐项可核验证据、最终文件 hash 和许可证/署名记录；所有 hero asset 具有 LOD、压缩纹理、回退路径和 dispose 测试；M01–M05 的天气、昼夜、海况、舰影、潜望镜、战术叠层、鱼雷和深水炸弹均完成真实浏览器截图；性能表在代表性目标设备得到签核；严格 TypeScript、全量自动测试与生产构建通过；以及最重要的，`git diff` 中没有 Simulation Engine、AI、任务、平衡或声呐规则的改动。
