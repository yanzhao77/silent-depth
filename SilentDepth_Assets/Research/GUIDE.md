# 潜艇资料研究规范

本目录是 SILENT DEPTH 潜艇资料库的总纲。每艘科技树潜艇的资料写在它自己的
`Documentation/` 下，本文件规定统一格式与执行方法。

**目标**：让建模者拿到一份资料，就能最大程度还原真实潜艇的外形、武器与设备；
并明确标出哪些已经有了、哪些还缺、哪些需要人工确认。

## 产出位置

每艘艇的资料写在自己资产的 `Documentation/` 下：

```text
SilentDepth_Assets/Submarines/<SSN|SSBN>/<国家>/<级>/
└── Documentation/
    ├── <ASSET_ID>_REFERENCE.md      详细资料（本规范定义的九节）
    ├── <ASSET_ID>_README.md         工厂生成的状态说明，不要改
    └── References/
        ├── PROVENANCE.json           每张图的来源、访问日期、许可
        └── NN_描述.jpg               参考图
```

`<ASSET_ID>` 用 manifest 里的 ID，例如 `US_SSN_LosAngeles`、`RU_SSBN_BoreiA`。

## 九节模板

标题必须完全一致，顺序不变。查不到的写 `UNKNOWN`，**不要留空、不要编造**。

```markdown
# <ASSET_ID> <中文常用名> / <英文级名>

> 资料状态：<见下方标记规范>　最后更新：YYYY-MM-DD

## 1. 身份与定位
...
## 2. 尺度与外形
...
## 3. 动力
...
## 4. 武备
...
## 5. 传感器与电子设备
...
## 6. 潜深与乘员
...
## 7. 建模要点
...
## 8. 待办与不确定项
...
## 9. 资料来源
...
```

### 各节要求

1. **身份与定位** — 国家、艇型（SSN/SSBN）、级/项目号、北约代号、服役期、同级建造数量、
   现役状态（截至资料日期）。同一级的不同批次（如 Flight、项目改进型）单列。

2. **尺度与外形** — 全长、艇体宽、吃水、水上/水下排水量；外形特征：
   围壳形状与位置、舵型（十字/ X 型、围壳舵/艏舵）、艉部构型、壳体线型、消音瓦、
   甲板与开口布局。**外形特征这节直接面向建模，越具体越好。**

3. **动力** — 反应堆型号与功率、蒸汽轮机/电力推进、推进器形式（螺旋桨叶数/泵喷）、
   轴数、水上/水下/静音航速。

4. **武备** — 发射管：数量、口径、**发射管长度**、布置位置（艇艏/艇艉/斜置）、
   发射方式（液压/自航）。可发射武器逐项列出：鱼雷、反舰导弹、巡航导弹、水雷，
   含型号、口径、**弹长**、用途。载弹总量与装填方式。

5. **传感器与电子设备** — 艇艏声呐、舷侧阵、拖曳阵（型号）、雷达、电子战/ESM、
   通信系统、潜望镜与光电桅杆数量。查不到型号就写功能与位置。

6. **潜深与乘员** — 工作深度、极限深度、编制人数。

7. **建模要点** — 用于还原的关键外形特征清单，逐条写；标注哪些已实现、哪些没做。

8. **待办与不确定项** — 本艇所有待办：模型几何缺口、材质/贴图缺口、文档缺口、
   需要人工确认的数据、来源冲突、纯推测项。**逐条列，不要合并。**

9. **资料来源** — 每条一行：`- [标题](URL)　访问 YYYY-MM-DD　许可：<状态>`。
   另外注明本艇共下载几张参考图（图片清单在 `References/PROVENANCE.json`）。

## 标记规范

正文中凡是涉及「有没有 / 缺什么 / 是否可靠」的地方，用下面这套标记，写在句末：

| 标记 | 含义 |
|---|---|
| `【已有】` | 仓库里已经有该资产或数据 |
| `【缺失】` | 应该要有但目前没有 |
| `【待建模】` | 外形特征尚未建模 |
| `【待确认】` | 资料存在冲突或来源不权威，需要人工核实 |
| `【推测】` | 公开资料没有，按同级艇或工程常识推断 |
| `【不许推断】` | 涉及敏感细节，公开来源不可靠，不做还原 |

已经落后的艇（Typhoon、Akula、Yasen）要特别标出**当前模型已经做成什么样**，
再对照真实特征逐条列差异。

## 检索方法

用 firecrawl CLI（已认证）。**注意配额**：搜索约 2 credits/次，抓取 1 credit/次，
当前额度有限，按下面的预算执行。

```bash
npx firecrawl search "<查询>" --limit 5 --json
npx firecrawl search "<查询>" --sources images --limit 10 --json
npx firecrawl scrape "<url>" -o .firecrawl/<名字>.md
```

每艘艇的预算：**约 3 次搜索 + 3 次抓取（≈9 credits）**。
优先顺序：

1. 该级艇的 Wikipedia 页面（英文优先，中文/俄文补充）
2. 专业资料站（weaponsystems.net、russianships.info、naval-technology、globalsecurity、
   fas.org、navypedia 等）
3. 官方公开来源（美国海军 fact file、厂商页面）
4. 图片：`--sources images` 一次，取前 6–10 张候选

资料稀少的艇（尚未服役或高度保密：Type 095、S5、SNLE 3G、SSN-AUKUS 等）
不要为了凑字数反复检索，如实写 `UNKNOWN` 并标注 `【推测】`。

## 图片规则

- 每艘艇下载 **4–6 张**最有参考价值的图（侧视线图、俯视图、实艇照片、结构示意），
  存到该艇的 `References/`，命名为 `01_侧视.jpg` 这样的序号+描述。
- 每张图在 `PROVENANCE.json` 里记：文件名、来源页面 URL、原始图片 URL、访问日期、
  许可/版权状态、简要说明。
- 优先 Wikimedia Commons / 公有领域 / 官方公开照片；来源不明的照常下载入库，
  但许可字段必须如实写 `UNKNOWN`。
- **所有参考图只用于本地审阅，不得进入运行时资产包。**

`PROVENANCE.json` 结构：

```json
{
  "asset_id": "US_SSN_LosAngeles",
  "generated_at": "2026-09-10",
  "note": "参考图仅供本地审阅，不进入运行时资产包。",
  "images": [
    {
      "file": "01_profile.jpg",
      "source_page": "https://...",
      "image_url": "https://...",
      "accessed": "2026-09-10",
      "license": "UNKNOWN | Public Domain | CC BY-SA 4.0 | US Navy (public domain)",
      "description": "侧视线图"
    }
  ]
}
```

## 写作要求

- 全部用简体中文（型号、代号、API 名保留原文）。
- 数字带单位；同一数据有多个来源且冲突时，把两个都写上并标 `【待确认】`。
- 不写"可能""大概"这种模糊表述，改为明确标注 `【推测】`。
- 不抄大段原文，用中文归纳，关键专有名词保留英文。
- 每份文档控制在 150–400 行，信息密度优先，不要注水。
